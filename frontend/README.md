# Frontend and Backend Server (Node.js)

## Backend

### Overview

This Node.js server acts as the backend for the React frontend UI (`frontend-ui`). It serves as an API gateway and orchestrator, handling requests from the UI, processing file uploads, interacting with the Python-based backend microservices, and returning aggregated results.

### Technology Stack

*   **Node.js:** JavaScript runtime environment.
*   **Express:** Web framework for Node.js.
*   **Multer:** Middleware for handling `multipart/form-data`, used for file uploads (resumes).
*   **node-fetch:** For making HTTP requests to the backend microservices.

### Functionality

1.  **API Endpoint (`/api/analyze`):**
    *   Receives `POST` requests from the frontend UI.
    *   Expects `multipart/form-data` containing:
        *   `resume`: The uploaded resume file (PDF, DOCX).
        *   `jobDescription`: The text of the job description.
        *   `jobTitle` (optional): The job title.
2.  **File Handling:**
    *   Uses `multer` to temporarily store the uploaded resume file.
3.  **Microservice Orchestration:**
    *   Calls the `job-title-detector` service (if `jobTitle` is not provided) to extract the job title from the job description.
    *   Calls the `keywords-extractor-openai` service to extract relevant keywords from both the resume text and the job description.
    *   Calls the `match-scorer-openai` service to calculate the match score and generate feedback based on the resume and job description.
4.  **Response Aggregation:**
    *   Combines the results from the microservices into a single JSON response.
    *   Handles potential errors or timeouts from the microservices.
5.  **Cleanup:**
    *   Deletes the temporarily uploaded resume file after processing.

### Configuration

The server relies on environment variables to know the URLs of the backend microservices. These are typically set within the Kubernetes deployment (`frontend/deployment/dev/backend.yaml`):

*   `JOB_TITLE_DETECTOR_URL`: URL for the Job Title Detector service (e.g., `http://job-title-detector:5000`).
*   `KEYWORDS_EXTRACTOR_URL`: URL for the Keywords Extractor service (e.g., `http://keywords-extractor-openai:5000`).
*   `MATCH_SCORER_URL`: URL for the Match Scorer service (e.g., `http://match-scorer-openai:5000`).

### Running Locally (Development)

```bash
# Navigate to this directory
cd frontend/backend

# Install dependencies
npm install

# Set environment variables (example)
export JOB_TITLE_DETECTOR_URL=http://localhost:5001 # Adjust ports as needed
export KEYWORDS_EXTRACTOR_URL=http://localhost:5002
export MATCH_SCORER_URL=http://localhost:5003

# Start the server
npm start
# or using nodemon for auto-reload
# npm run dev
```

*(Note: Ensure the backend microservices are also running locally and accessible at the specified URLs/ports.)*

### Docker Build

The Docker image for this server is built using the Dockerfile located at `frontend/docker/backend.Dockerfile`. The build process is typically managed by the Makefile in the `frontend` directory (`make build-backend`).

### Kubernetes Deployment

This server is deployed to Kubernetes using the manifest file located at `frontend/deployment/dev/backend.yaml`. This manifest defines the Deployment (to manage the pods) and the Service (to provide internal network access). Deployment is typically handled by the Makefile (`make deploy-backend`).

## Frontend (React UI)

### Overview

This is the user interface for the Resume-ATS application, built using React. It allows users to upload their resume, provide job description details, and view the analysis results generated by the backend system.

### Technology Stack

*   **React:** JavaScript library for building user interfaces.
*   **Vite:** Fast frontend build tool and development server.
*   **CSS:** Styling the application components.

### Functionality

1.  **Resume Upload:** Allows users to select and upload a resume file (PDF, DOCX).
2.  **Job Details Input:** Provides fields for users to paste the job description and optionally enter the job title.
3.  **Analysis Trigger:** A button ("Analyze Match") sends the resume file and job details to the backend server's `/api/analyze` endpoint.
4.  **Results Display:** Renders the analysis results received from the backend, including:
    *   Overall match score (using a gauge).
    *   Breakdown by categories (Skills, Experience, etc.).
    *   Keyword analysis (matched and missing keywords).
    *   Improvement suggestions.
5.  **Loading State:** Shows a loading indicator while the analysis is in progress.

### Configuration

The frontend needs to know the URL of the backend server's API. This is configured using the `VITE_REACT_APP_API_URL` environment variable during the build process (managed by Vite).

*   In Kubernetes, the frontend typically calls `/api/analyze`, relying on the Ingress to route the request to the backend server.
*   For local development, this might be set to `http://localhost:5000` (or wherever the backend server is running locally).

### Running Locally (Development)

```bash
# Navigate to the frontend UI directory
cd frontend/frontend-ui

# Install dependencies
npm install

# Start the Vite development server
npm run dev
```

The application will typically be available at `http://localhost:5173` (or another port specified by Vite).

*(Note: Ensure the backend server (`frontend/backend`) is also running locally and accessible for API calls.)*

### Docker Build

The Docker image for the frontend UI is built using the Dockerfile located at `frontend/docker/frontend-ui.Dockerfile`. This typically involves:
1.  Building the static React application using `npm run build`.
2.  Serving the static files (`dist` directory) using a web server (like Caddy or NGINX).

The build process is managed by the Makefile in the `frontend` directory (`make build-frontend`).

### Kubernetes Deployment

The frontend UI is deployed to Kubernetes using the manifest file located at `frontend/deployment/dev/frontend.yaml`. This manifest defines the Deployment (to manage the pods serving the static files) and the Service (to provide internal network access). Deployment is typically handled by the Makefile (`make deploy-frontend`). Access is provided via the Kubernetes Ingress resource.
